# Кампании Keitaro

Обёртка над трекером Keitaro (тестовое задание, см. [`TASK.md`](TASK.md)):

1. **Создаватор кампаний** — по имени, гео и офферу создаёт кампанию с двумя потоками: поток 1 отправляет трафик из выбранных стран на Google, поток 2 — на офферы.
2. **Редактор кампании** — добавляет и удаляет офферы во втором потоке; доли делятся поровну, остаток получает последний оффер (3 оффера → 33/33/34).

Стек: FastAPI + SQLAlchemy + Alembic + Postgres (бэкенд), Svelte 5 + Vite + TypeScript + Tailwind (фронт), pnpm workspace.

## Что нужно установить

| Инструмент | Версия       | Как поставить                                             |
| ---------- | ------------ | --------------------------------------------------------- |
| Node.js    | 24+          | https://nodejs.org                                        |
| pnpm       | 12.16.1      | `corepack enable` (pnpm возьмёт версию из `package.json`) |
| uv         | 0.10+        | https://docs.astral.sh/uv/ — Python 3.13 uv скачает сам   |
| Docker     | любая свежая | для Postgres                                              |

## Настройка

1. Скопируйте шаблон переменных:
   ```sh
   cp .env.example .env
   ```
2. Впишите в `.env` ключ API: админка Keitaro → Профиль → API ключи → `KEITARO_API_KEY`.
   Остальные значения в шаблоне уже рабочие (группа и источник `FORTESTS`, страна по умолчанию `AU`).

   > **Домен выбирается в форме, а не в `.env`.** В задании указан домен `in.posdk.xyz`, но в трекере его нет: API отдаёт только `kylovoa.com`. Поэтому форма создания показывает дропдаун «Домен» со всеми доменами трекера (`GET /domains`), первый выбран сразу. Если `in.posdk.xyz` появится в трекере, его можно будет выбрать без правок кода.

3. Поставьте зависимости:
   ```sh
   corepack enable
   pnpm install
   uv sync --directory backend
   ```
4. Поднимите Postgres (заодно создаётся база `keitaro_test` для тестов):
   ```sh
   docker compose up -d db
   ```
   Postgres доступен на порту **5434** (не 5432): так он не конфликтует с другими Postgres на машине.
   Если `.env` у вас уже был со старым портом, поменяйте в `DATABASE_URL` `:5432/` на `:5434/`.
   База `keitaro_test` создаётся только при первом запуске, на пустом томе. Если том `pgdata` остался от старой версии без неё, пересоздайте его: `docker compose down -v && docker compose up -d db`.
5. Создайте таблицы (миграции Alembic лежат в `backend/migrations/versions`):
   ```sh
   pnpm db:migrate
   ```
   Новая миграция после изменения моделей в `backend/app/adapters/db/models.py`. Alembic сравнивает модели с базой, поэтому база должна быть на последней миграции (`pnpm db:migrate`):
   ```sh
   uv run --directory backend alembic revision --autogenerate -m "что изменилось"
   ```

## Запуск для разработки

```sh
pnpm dev
```

Бэкенд — http://127.0.0.1:8000 (Swagger: `/docs`), фронт — http://localhost:5173 (запросы `/api` проксируются на бэкенд). Если порт 5173 занят, Vite возьмёт следующий свободный и напишет адрес в консоли.

## Как пользоваться

1. **Новая кампания.** Введите окончание имени (префикс `test_kondrashin_` подставляется сам), выберите домен, страны для редиректа на Google и оффер. После создания кампания открывается в редакторе.
2. **Редактор.** Выберите кампанию слева. Полоса показывает, как трафик делится между офферами; при добавлении или удалении оффера рядом появляется полоса «После сохранения», а таблица — «было → станет». Изменения уходят в Keitaro только по кнопке «Сохранить офферы».
3. Keitaro не сообщает о правках в своей админке, поэтому редактор сам перечитывает кампанию: каждые 10 секунд, пока вкладка открыта, при возврате на вкладку и по кнопке «Обновить». Несохранённую правку фоновое обновление не трогает: если поток в Keitaro изменился, над таблицей появится предупреждение, а свежие данные подставит кнопка «Обновить». Если фоновое обновление не прошло, ошибка видна под кнопкой. Несохранённая правка переживает перезагрузку вкладки (F5): черновик лежит в `sessionStorage` браузера.
4. Если поток изменили в Keitaro, пока вы правили, сохранение откажет и подтянет свежие данные, оставив вашу правку — проверьте её и сохраните ещё раз.
5. Адрес страницы запоминает выбранную кампанию (`#/campaigns/<ID>`): её можно перезагрузить или отправить ссылкой.

## Проверки

```sh
pnpm test   # pytest (бэкенд) + vitest (фронт); нужен запущенный Postgres (шаг 4)
pnpm lint   # ruff + prettier + svelte-check
```

Один тест: `uv run --directory backend pytest tests/test_health.py::test_health`.

CI (GitHub Actions) в репозитории нет: на бесплатном аккаунте GitHub закончились лимиты. Проверки запускаются локально командами выше.

## Ограничения тестового трекера

- В трекере один оффер (18813), а ключ API не может создавать офферы (`POST /offers` → 403). Поэтому на живых данных редактор работает с одним оффером. Деление долей (3 оффера → 33/33/34) проверяют тесты (`pnpm test`) и показывает превью долей в редакторе.
- Если оффер выключен в Keitaro вручную (`state: disabled`), он остаётся в потоке со своей долей, но трафик не получает. Редактор показывает такой поток как «неровный» и предупреждает пользователя. Сохранение не включает оффер обратно: Keitaro сохраняет его `state`, и включить оффер можно только в админке Keitaro.
- Перед трекером стоит Cloudflare: он отклоняет запросы с User-Agent библиотек (`error code: 1010`). Бэкенд отправляет свой User-Agent.

## Типы API для фронта

Типы в `packages/api-types` генерируются из OpenAPI-схемы FastAPI. После изменения API выполните:

```sh
pnpm gen:api
```
